# Initial viewer behavior

Lulo is a native macOS 14+ image viewer implementing [issue #2](https://github.com/jiahuei/lulo/issues/2). It has no editing, catalog, account, analytics, network, or cloud functionality. Metadata and ratings are embedded-image data only; sidecars and RAW decoding are outside this version.

## Opening and navigation

Finder and File > Open reuse one viewer window. The initial window fills the screen's available work area as a normal window, without entering macOS full-screen mode. Opening a file resets filters, collapses metadata, and selects Fit to Window. The sort method and sort direction persist in UserDefaults. Arrow navigation retains sorting, filters, sidebar visibility, and the current viewing mode; at 100%, it retains the same relative image region.

JPEG (including JPG), PNG, and HEIF (including HEIC) are supported. A direct RAW open produces an unsupported-format message. The app requests the containing folder before enumerating siblings. Canceling leaves the directly opened image viewable; File > Allow Folder Navigation can request access again. Grants last for the process lifetime or until replaced, with ongoing work retaining its own grant. There are no persisted bookmarks. Discovery is nonrecursive, excludes hidden files and symbolic links, and retains unreadable supported files so errors do not remove navigation choices. The directly opened file remains in the session while it exists, even if discovery skips it.

Left/right arrows on the image, toolbar navigation buttons, and Command-[ / Command-] navigate with wrapping. Use the menu shortcuts when a filter or metadata text control has keyboard focus. Missing, corrupt, unsupported, and inaccessible files produce recoverable messages.

## Refreshing images

Lulo automatically refreshes the current image, embedded metadata/ratings, and gallery when supported images change, appear, disappear, or are renamed in the authorized folder. Native FSEvents notifications are limited to that folder's immediate images and coalesced before refreshing. With only single-file access, a background check compares that file's size, modification time, and file identity once per second; it does not inspect siblings. This check also detects deletion and recreation. In-place changes that preserve those attributes require manual refresh. Monitoring retains its access grant and stops when another session replaces it.

Refresh is available in both views through the toolbar's refresh arrow and View > Refresh (Command-R). It bypasses both decoded caches, reloads the selected image, and rescans an authorized folder. Without a folder grant it reloads only the opened image. Refresh preserves gallery/image mode, sorting, filters, sidebar visibility, and the selection when it still exists and matches the filters; otherwise the first matching image becomes selected. Deleted entries, including the originally opened file, are removed after successful discovery. A missing single file remains a recoverable error so it can reload if recreated. An unreadable folder retains the existing list with a retry message. If native monitoring cannot start, the status bar directs the user to Refresh.

Automatic refresh waits while a sheet or Trash operation is active; manual refresh is unavailable then. New refreshes cancel obsolete scans, image loads, and thumbnail requests. Opening another image rejects callbacks from the previous session. Both cache budgets remain unchanged; normal cache reuse continues between refreshes.

## Moving images to Trash

Move to Trash is available from the toolbar and File menu (Command-Delete) for the currently displayed image. A confirmation names the image, with Cancel as the default. The action is unavailable in gallery mode, while loading, during another Trash operation, while a sheet is open, or without a displayed image. It moves one image to the macOS Trash; there is no permanent-delete fallback, bulk action, or in-app undo. Recover trashed images in Finder.

After success, the next image in the current filtered/sorted order becomes selected, wrapping at the end. If no images remain, the viewer offers Open Image; if filters exclude the remaining entries, Clear Filters remains available. A failed operation reports an error and retains the current selection. Navigation and new opens remain usable during the background operation, whose completion cannot replace another session. Obsolete folder scans cannot reintroduce a trashed entry.

The sandbox grants read/write access only to user-selected files and folders to support this explicit action. Opening and viewing never write image contents or metadata. The Trash operation retains its access grant through completion and rejects directories and symbolic links, including those with image extensions.

## Interface

The image occupies the main workspace with an 8-point fit inset and rounded corners. The canvas paints the image once without a shadow. The D9 interface uses SF Pro, a neutral grey wall in light appearance and a near-black wall in dark appearance, with blue accents. A transparent titlebar holds a breadcrumb and four rounded toolbar capsules, ordered Gallery / Open / Refresh, Previous / Next, Display / Blurred Background, and Sort & Filter / Metadata / Trash. Buttons and segments use native AppKit drawing, SF Symbols, pressed/disabled states, keyboard focus, tooltips and accessibility labels. Content follows the window safe area as the toolbar appears or hides. Refresh uses the original system arrow; a user-started refresh animates until its work completes, except under Reduce Motion. Automatic refresh leaves the icon still.

The breadcrumb shows only the authorized folder's parent and folder, followed by the filename in image view. Its folder button opens Gallery; the parent is display-only. Single-file access shows only the filename and the initial empty state shows no breadcrumb. The full displayed location is available as a tooltip and accessibility value. The parent hides below 1000 points; folder and filename truncate at narrower sizes. The visual window title is hidden, but the actual title continues to identify the file or gallery folder in system UI.

Gallery (also View > Toggle Gallery or Command-G) uses the authorized folder's existing order, exact-rating filters and selection. If folder access was declined, Gallery requests it again; canceling keeps the single-image viewer. Return, double-click or the Preview poster's View button opens the selection. Left/right arrows wrap through the order; up/down choose the nearest horizontal center in the adjacent row. Metadata and Trash remain disabled in Gallery. Entering Gallery resets to Fit to Window. Returning to image view keeps Fit and restores metadata-panel visibility. A new explicit open returns to image view and resets the session as usual.

Gallery has two persisted layouts. **Rows**, the default, has a folder heading and count above justified, aspect-preserving rows, with six-point gaps. Row breaks choose the height closest to the target. The final row is left-aligned and no taller than the target or the preceding row. Filenames appear on hovered and selected tiles. **Preview** has a large selected-image poster left-aligned and centered vertically in the space between the folder heading and a bottom-pinned caption. The filename, rating, capture/exposure details and View button stay at the bottom of the left column beside a square cropped grid with six-point cell gaps and a one-point image inset (eight points between visible images). Rating chips are centered alongside the filename with equal text padding. It uses the thumbnail until the full-resolution image is available from the existing image store. Grid filenames remain available through accessibility and tooltips. Failed tiles remain selectable and show their filename and Preview unavailable.

The Display capsule replaces the viewing-mode toggle with Rows / Preview and a thumbnail-size slider in Gallery. View > as Rows / as Preview (Command-1 / Command-2) also opens Gallery when needed. Switching closes Sort & Filter and retains selection in view. Rows targets 120-300 points in steps of ten (default 200); Preview uses a minimum tile size of 88-220 points, changing by six (default 128). Each size is saved separately. Smaller/larger buttons and Command-minus / Command-plus (also Command-equals) move two steps; all four arrow keys on the focused slider and accessibility increment/decrement move one step. All inputs and restored preferences use the same size grid anchored at the default; endpoints remain reachable with a shorter final step. Below 900 points, the buttons hide, the slider shrinks to 64 points, Rows side padding is 18 points and the Preview poster column is 300 points. Both layouts support a 720-point window.

Numbered star pills at the upper-right of tiles replace star rows: one gold star followed by the rating. Ratings remain read-only and VoiceOver announces filename and N of 5 stars. Zero and missing ratings show no pill. Inline numbered chips appear in the image status line, Preview caption and metadata header. The Sort & Filter rating choices retain their existing labels.

**Blurred Background** is available in both modes, in the Display capsule and View menu (Option-Command-B). It is saved globally and defaults to plain. It uses the selected image's existing 320-pixel thumbnail, processed away from the main actor into light/dark blurred variants with a light veil or dark wash/vignette. Only the current background variants are retained. Image changes crossfade over 0.5 seconds and toggling over 0.35 seconds; Reduce Motion makes both instant and disables Preview hover scaling. Background requests retain authorization and reject obsolete selections. Count, caption and status text use primary color over blur. Layout, sizes and background are not reset by explicit opens.

Thumbnail decoding runs serially off the main actor, separately from full-resolution image loading. Image I/O fits each preview within 320 by 320 pixels while retaining orientation, aspect ratio, alpha, and color information; the same 64-megapixel source limit applies. Visible collection items, the selected Preview poster and an enabled blurred background share the same thumbnail loader. Cells release their previews and cancel pending requests when they leave view, the grid reloads, or gallery mode closes; reused cells reject old results. A separate least-recently-used cache retains up to 1 GiB of decoded thumbnail pixels, without an image-count limit. Cached previews survive scrolling, sorting/filter changes, switching views, and opening other files; every revisit checks file size, modification time, and file identity before reuse. Completed decodes remain reusable when the original cell cancels, while canceled queued requests skip decoding. Cache entries retain pixels rather than file-access grants; each request retains its current grant until completion. A failed preview keeps its filename and shows Preview unavailable, and the image can still be opened to show the normal recoverable error. No matching images offers Clear Filters.

Sort & Filter opens a transient popover with labeled sort and direction controls plus rating and file-type checkboxes. Rating choices occupy two equal-width columns, ordered downward: Unrated / 0 Stars, 1 Star, and 2 Stars on the left; 3 Stars, 4 Stars, and 5 Stars on the right. Changes apply immediately. The Sort & Filter button reports the number of checked rating and file-type boxes (0-9) in a visible badge, tooltip and accessibility label, with singular wording for one. The badge is hidden at zero and is not a separate accessibility element, and the status bar names those filters beside the image position. Clear Filters is available both in Sort & Filter and in the no-matches state. New explicit opens dismiss Sort & Filter and return keyboard focus to the image.

The initial empty state offers Open Image, cache misses use a compact translucent loading box with a native spinner and the incoming filename, and failed image loads offer Open Another Image. Cached next and previous images skip the loading overlay, including images already decoded by prefetch. Navigation retains the previous image and its zoom/pan while checking the cache or decoding, then swaps in the completed image in the selected viewing mode, retaining the relative viewing position at 100%. A new selection dismisses any previous loading overlay; only a current request that needs decoding can show it again. Late loading notifications cannot cover an already displayed image or a newer selection. Metadata is cleared while loading so it cannot be mistaken for the incoming file. Errors and empty filters clear the retained image. Long loading filenames truncate in the middle, with the full name available to accessibility and a tooltip. The floating metadata panel has a filename/capture/rating header, distinct group headings, tertiary field labels and selectable, wrapping values. It is 300 points wide with rounded translucent material and 14-point right/bottom margins, and reserves image space instead of overlapping it.

The design/development pass used [nice-skills design-research](https://github.com/EmbeddedLLM/nice-skills/tree/a11b1778ac52bd3fd08bc68290ecb09fcadb3b77/skills/design-research) and [software-workflow](https://github.com/EmbeddedLLM/nice-skills/tree/a11b1778ac52bd3fd08bc68290ecb09fcadb3b77/skills/software-workflow). The relevant guidance was actionable empty states, visible focus, labeled controls, and preserving the established platform. The catalog does not cover AppKit; native integration follows [Apple's toolbar guidance](https://developer.apple.com/design/human-interface-guidelines/toolbars). No skill scripts or dependencies run inside Lulo.

The image-view status bar displays the loaded image's embedded rating as a numbered star chip, with an accessible spoken rating. Zero or missing ratings show no stars. Ratings are read-only and hidden while loading, on errors, and in Gallery, whose thumbnails have their own rating overlays. The 34-point status line keeps position, rating and accent-colored filter summary on the left and the viewing scale (Fit, percentage or 100%) on the right.

## Display

Fit to Window is the initial viewing mode. It preserves aspect ratio, shows the entire image, and leaves unused viewport space. The Viewing mode toggle shows the current choice and changes it directly to fit or 100%, centering the image. Double-click updates the same mode and toggle. Viewing mode is not persisted: reopening the app or its closed viewer window, explicitly opening an image, or entering Gallery resets it to Fit to Window, including for users with an older saved 100% default. At 100%, one decoded source pixel occupies one backing pixel, independent of print DPI. Backing conversions are recalculated for the current view when resizing or moving between displays. macOS scaled display modes may further transform backing pixels before physical display output.

Scrolling upward over the image increases zoom; downward decreases it. Natural-scroll device direction is normalized. Double-click toggles between Fit to Window and 100%. When zooming to 100%, the image point under the cursor stays under the cursor, constrained by the image edges. Next/previous navigation preserves the selected mode and the relative image position at the center of the viewport, including after panning and across different image dimensions. Images smaller than the viewport remain centered on that axis; pan is constrained to the image edges. Manual scrolling is temporary and leaves the selected mode unchanged: navigation reapplies that mode, and double-click returns to 100% (or fit if already exactly at 100%). Drag an oversized image to pan. Temporary zoom is limited to 1%–3200%.

Image I/O applies orientation during decoding; Core Graphics draws the resulting image with its color space and alpha. A serial image-store actor keeps decoding off the main actor, separate from folder metadata discovery. Obsolete scans check cancellation before directory listing, before and after each metadata read, and before returning results. Opening another session cancels the scan and rejects any already-queued completion; its security-scoped grant stays alive until the worker exits. An in-progress directory listing or individual Image I/O metadata read must finish before its next cancellation check. A 64-megapixel input limit bounds each decode; larger images show a recoverable limit message rather than silently substituting reduced resolution at 100%.

Navigation retains the filtered/sorted order until entries, filtering, or sort preferences change. A least-recently-used cache retains at most ten full-resolution images and at most 1 GiB of decoded pixel buffers; metadata is retained alongside each image. Revisits check file size, modification time, and file identity before reuse; explicit opens start a new cache generation. One adjacent image in the current navigation direction is prefetched only within authorized files. Changing direction, filters, sorting, or opening a new image cancels obsolete queued prefetch work. An already-running Image I/O decode cannot be interrupted; its result can populate the cache but cannot replace a newer selection.

The two independent cache budgets allow up to 2 GiB of retained decoded pixels in total. They exclude displayed images/thumbnails when evicted, active decodes, metadata and cache bookkeeping, Image I/O working memory, and display buffers. A typical 8-bit RGBA image at the input limit occupies about 256 MiB. Prefetch failures remain silent until that file is selected, when the usual recoverable error is shown. Full-resolution pixel data and metadata are unchanged by reuse. Both caches are memory-only and share strict byte accounting, least-recently-used eviction, and file validation.

## Sorting and filtering decisions

- Initial order is ascending natural filename order (`photo2` before `photo10`). Filename comparison uses the user's locale, with a literal URL fallback for otherwise equal names.
- Sort choices are Name, Time Taken, Star Rating, and File Type. File Type groups JPEG aliases and HEIF aliases together.
- Descending reverses both primary values and filename tie-breaks.
- Time Taken uses embedded Date Time Captured (EXIF DateTimeOriginal), then file creation time. Embedded timezone offsets are honored; timestamps without offsets are compared as UTC wall-clock values rather than guessed local zones.
- Files without the selected date/rating metadata form a group after known values in both directions. Within that group filenames determine order. This produces a transitive sort rather than a pairwise filename fallback that can contradict timestamp ordering.
- Star checkboxes match exact ratings; multiple checked ratings combine with OR. Unrated / 0 Stars includes absent, unsupported, and zero embedded ratings. Recognized XMP ratings are integers from 0 through 5; rejected/invalid ratings are treated as unrated.
- File-type checkboxes allow any combination of JPEG, PNG, and HEIF. Multiple checked types combine with OR.
- Rating and file-type groups combine with AND. Each group starts unchecked, meaning all values; unchecking the last value also removes that group's restriction. Clear Filters unchecks both groups. The toolbar counts every checked box, including fully checked groups, and the status bar lists checked values in rating/type order.
- Filtering retains the selected image if it still matches; otherwise it selects the first image in the new ordered set. With no matches, the viewer displays “No images match the current filters.” Clearing filters selects the first image if the selection was empty.

## Metadata

The floating metadata panel starts collapsed and displays available values in these read-only groups:

| Group | Fields |
| --- | --- |
| File | File Name, File Path, Dimensions |
| Timestamps | Date Time Captured, Date Time Digitized, Date Time Modified |
| Exposure | Exposure (shutter speed and aperture), Focal Length, Focal Length 35mm, Brightness Value, Exposure Bias, ISO Speed Rating, Flash, Exposure Program, Metering Mode |
| Camera and lens | Make, Model, Serial Number, Lens |
| Location | GPS, Altitude, Direction |
| Attribution and comments | Artist, Software, User Comment |

Missing fields are omitted. Dimensions are orientation-adjusted source dimensions, not the zoomed viewport size. Date Time Captured reads EXIF DateTimeOriginal; Date Time Modified reads the EXIF/TIFF DateTime tag, not Finder modification time. Source tags and values are unchanged. Flash, exposure program, and metering mode currently display embedded numeric codes. The screenshot referenced in issue #2 supplied only the field list; its image and personal metadata are not fixtures.

## Architecture and platform references

`LuloCore` owns value types for preferences, session selection, sorting/filtering, and zoom. `LuloImaging` uses Foundation and Image I/O for metadata, decoding, directory discovery, and security-scoped access. The AppKit application owns the single window, native controls, permission panels, rendering, a background folder-discovery queue, and a serial image-store actor. UI state stays on the main actor. Session generations reject old folder scans; request identifiers reject old image loads.

There are no external package dependencies or copied upstream application sources. These native APIs inform the implementation:

- [Apple: accessing files from the macOS App Sandbox](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)
- [Apple: balanced security-scoped resource access](<https://developer.apple.com/documentation/foundation/nsurl/startaccessingsecurityscopedresource()>)
- [Apple: Image I/O image sources and transformed thumbnails](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/ImageIOGuide/imageio_source/ikpg_source.html)
- [Apple: backing scale and coordinate conversions](https://developer.apple.com/documentation/appkit/nswindow/backingscalefactor)
